Lesson 1: Read the System Before the Files

Goal: Build the mental model needed to explain Ledgerly without memorizing filenames.

The core idea

Ledgerly is a pipeline. Raw financial input enters through a browser, becomes a validated structured record, is saved under an authenticated tenant, and is then queried into views, analytics, exports, and optional aggregate-only insights.

browser → API → authenticated scope → validation/parser → Prisma → PostgreSQL → response → cached UI
Interview anchor: the frontend requests actions; the backend decides identity and ownership; the database provides a second isolation barrier.

How to navigate the repository

  1. Start with README.md, docs/PRD.md, and the graph report to learn intended behavior and vocabulary.
  2. Read the backend entry point apps/backend/src/index.ts to see middleware and route composition.
  3. Follow imports into tenant.ts, db.ts, shared contracts, and feature services.
  4. Trace one vertical flow end to end instead of reading all UI files as unrelated components.

Retrieval checkpoint

Without looking at the code, answer: (1) What is the security boundary? (2) Where is raw text parsed? (3) Which layer owns user and organization IDs? (4) What does the frontend cache after a mutation?
